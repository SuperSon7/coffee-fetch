# Coffee Fetch — 첫 버전 제품 정의

상태: 검토용 초안. 대화에서 합의한 방향과 아직 검증하지 않은 제안을 구분한다.

## 목적과 기본 방향

관심 기술의 새 소식을 부담 없는 양으로 읽고, 다시 볼 자료를 저장한다. 기존 AI 예약 요약과 달리 편한 읽기 화면과 읽음·저장 기록을 제공하는 데 가치를 둔다. 모든 트렌드를 따라가는 것을 목표로 삼지 않는다.

- 프로젝트명: Coffee Fetch
- 관심 분야: IT, DevOps, Cloud, AI, Observability
- 관심 도구: Kubernetes, Grafana, Python 및 관련 도구
- 기본 사용 방식: 관심 기술의 새 소식 받기
- 고민 기반 검색·추천: 선택적인 후속 기능. 처음 사용하기 위한 필수 입력이 아니다.
- 개발 환경: WSL 예정. 이번 작업은 문서 정리와 저장소 생성이며 서비스 구현은 시작하지 않는다.

## 첫 버전 범위 제안

1. 관심 분야·도구, 발행 주기, 분량 설정
2. 공식 블로그·릴리스·행사 발표의 새 자료 수집
3. 중복을 줄인 짧은 한국어 카드와 원문 링크
4. 원문 열기, 읽음 표시, 나중에 보기
5. 지난 브리핑과 저장 자료 조회
6. 수집 실패와 새 소식 없음 구별

평일 오전 8시, 하루 3장 또는 5분 분량은 시험할 기본값이며 확정 사양은 아니다. 중요한 소식이 없으면 분량을 억지로 채우지 않는다. 사용 버전을 모르면 실제 영향을 단정하지 않는다.

## 핵심 화면 제안

| 화면 | 역할 |
|---|---|
| 관심사 설정 | 도구·분야와 시간·분량 선택 |
| 오늘의 브리핑 | 핵심 요약, 출처, 발표일, 원문 링크, 읽음·저장 |
| 나중에 보기 | 저장한 자료를 다시 찾고 정리 |

카드는 무엇이 새로 나왔는지 2~3문장으로 설명한다. 모든 카드에 억지로 개인화 이유를 생성할 필요는 없다. 원문 링크 클릭과 실제 읽음은 구분한다.

## 행사 발표 처리

제목·소개로 먼저 후보를 선별한다. 발표 전체 요약은 자막·슬라이드 등 근거를 확보한 경우에만 제공한다. 소개만 확보했으면 소개 기반임을 표시한다. 발표가 많아져도 사용자에게 보여주는 일일 분량은 제한한다.

## AI 역할과 실행 방식

수집·URL 중복 제거·일정 실행·기록 저장에는 AI가 필수가 아니다. AI는 짧은 요약, 관련성 분류, 같은 사건 묶기를 보조한다. 로컬 LLM과 외부 API 중 어느 것이 적합한지는 실제 자료와 하드웨어를 평가한 뒤 결정한다.

야간에 수집·선별·요약하고 결과를 저장해 앱에서는 저장된 결과를 표시하는 방식을 검토한다. PC 절전·종료 시 보완 실행이 필요하다. 야간 실행은 메모리 제약이나 요약 오류를 해결해주지는 않는다.

## 보류한 아이디어

- 관심 줄이기
- 저녁에 읽은 것과 메모 정리
- 주간 회고와 써볼 아이디어 목록
- 고민 기반 추천
- 영어 공부 앱 같은 복습·학습 경험
- 긴 발표 전체 분석과 정교한 추천 학습

위 아이디어는 폐기가 아니라 사용 경험을 확인한 뒤 판단할 후보다.

## 프로젝트의 학습 목적

재미와 제품 개발 역량 향상을 위해 기획·목업·설계·구현·검증·배포·운영을 작은 범위로 한 번 완주한다. 단계별 결정과 AI 활용 효과, 재작업과 병목을 [작업 기록](work-log.md)에 남긴다. 절차의 양보다 결정의 근거와 실제 사용 결과를 중시한다.
