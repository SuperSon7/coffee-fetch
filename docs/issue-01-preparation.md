# #1 진행 준비 — 학습 목표와 MVP 완료 기준

상태: 사용자 검토용 초안. 아래 목표·수치·시간은 제안이며 확정하지 않았다. [이슈 #1](https://github.com/SuperSon7/coffee-fetch/issues/1)은 열린 상태로 유지한다.

## 이번 세션에서 끝낼 일

학습 목표 2개에서 3개, 제품 완료 기준, 첫 프로세스 개선 실험을 선택하고 제품 정의서에 반영한다. 구현·상세 데이터 설계·도구 선정은 다음 티켓에서 다룬다. 예상 집중 시간은 30분에서 45분을 제안하며 실제 시간은 사용자가 기록한다.

## 이미 정한 제품 범위

1. 목적: 관심 기술의 새 소식을 부담 없는 양으로 읽기
2. 초기 설정: 관심 분야·도구, 받을 주기, 읽을 분량
3. 화면: 짧은 요약 카드와 원문 링크
4. 행동: 원문 열기, 명시적 읽음 표시, 나중에 보기
5. 기록: 지난 브리핑과 저장한 소식
6. 보류: 고민 기반 추천, 저녁 회고, 학습·복습, 관심 줄이기

개인적인 재미와 AI를 활용한 제품 개발 역량 향상이 프로젝트의 목적이다. 작은 범위로 기획·목업·설계·개발·배포·사용 회고를 경험한다.

## 선택할 학습 목표 — 추천 초안

| 후보 | 할 수 있게 되고 싶은 일 | 확인할 근거 |
|---|---|---|
| 제품 판단 | 모호한 아이디어를 작은 범위와 완료 기준으로 바꾸기 | 포함/제외 이유와 실제 사용 피드백 설명 |
| AI 협업 | AI에 적절히 작업을 나누고 결과를 검증하기 | 직접 선택한 결정과 AI 결과의 수정·검증 사례 |
| 끝까지 전달 | 설계한 기능을 배포하고 문제를 진단·복구하기 | 실제 실행 환경, 검증 기록, 운영·복구 절차 |

위 세 가지 중 우선순위를 정한다. 특정 기술 숙련이 더 중요하다면 한 항목을 바꿀 수 있다. 이해도는 AI에게 설명을 받았다는 사실이 아니라 본인이 구조·선택 이유·실패 가능성을 설명할 수 있는지로 확인한다.

## 제품 완료 기준 — 검토 초안

- [ ] 본인이 설정한 관심사·주기·분량이 다음 실행에도 유지된다.
- [ ] 실제 자료로 만든 회차에서 요약·출처·날짜·원문을 확인한다.
- [ ] 읽음과 저장이 구분되고 재접속 뒤에도 유지된다.
- [ ] 지난 회차와 저장한 자료를 다시 찾는다.
- [ ] 새 소식 없음과 수집 실패가 구분되며 반복 실행으로 회차가 중복되지 않는다.
- [ ] 선택한 환경에 배포하고 본인이 접근해 핵심 흐름을 직접 확인한다.

완료와 유용성을 구분한다. 위 항목은 기능 완료 기준이다. 유용성은 배포 후 1주 동안 실제 이용일·읽고 싶어 원문을 연 사례·다시 찾은 자료·불편을 기록해 판단한다. 사용하지 않았더라도 기록을 숨기지 않고 원인을 다음 개선으로 연결한다. 이용 횟수 목표는 지금 임의 확정하지 않는다.

## 첫 개선 실험 — 추천 초안

- 관찰: 이전 논의에서 단계 순서와 도구 선택을 여러 번 다시 논의했다.
- 가설: 시작할 때 결정할 질문과 완료 조건을 적으면 불필요한 재논의를 줄일 수 있다.
- 바꿀 행동 하나: 각 작업 시작 시 결정할 질문과 완료 조건을 각각 한 문장으로 적는다.
- 기록할 지표: 완료 조건의 모호함 때문에 다시 한 작업 시간(직접 작업 시간의 일부). 발생하지 않으면 0, 측정 못했으면 미측정.
- 확인 시점: 첫 3회에서 5회 세션 후 원인 기록과 함께 검토한다. 과거 기준값이 없으므로 최초 세션을 기준선으로 삼고 개선 효과를 단정하지 않는다.
- 구분: 실제 새로운 정보 때문에 바뀐 결정과 완료 조건이 불명확해서 되돌아간 작업은 따로 기록한다.

## 사용자가 답할 세 가지

1. 가장 기르고 싶은 역량은 무엇인가? 추천 세 가지의 우선순위 또는 대체 목표.
2. 배포 후 어떤 경험이 있으면 이 제품을 만든 보람이 있겠는가? 본인의 문장으로 한 가지.
3. 오늘 이 결정을 위해 쓸 수 있는 시간은 얼마인가?

답변을 받은 뒤 제품 정의서와 실제 시작 기록을 확정한다. 제안된 내용을 사용자의 결정처럼 기록하지 않는다.
